1 · SOURCES AND INTAKE

Contracts arrive from where they already live

Connectors

  • Watched inbox folders
  • Google Drive
  • OneDrive and SharePoint (Microsoft Graph)
  • Contracts mailbox (IMAP attachments)
  • REST feeds: ERP and procurement systems
  • Upload, any number of files

Connector secrets are stored encrypted.

Runs by itself, reads only what changed

  • On a schedule, or as soon as a file appears
  • Each file fingerprinted: size, time, SHA-256 hash
  • Unchanged: skipped. Changed: re-read
  • Same bytes under another name: a duplicate, not stored twice
  • Every run and file logged, shown live in Admin
Intake is built so nobody has to upload anything in production. The connectors read where contracts already live: watched folders, Google Drive, OneDrive and SharePoint through Microsoft Graph, a contracts mailbox over IMAP, and REST feeds from ERP and procurement systems; uploads are there for ad hoc files. In the proof of concept the external systems are labelled simulators that speak the real APIs; a customer's own tenant replaces them. Credentials are stored encrypted. The pipeline runs on a schedule or as soon as a file appears. Each file is fingerprinted by size, modified time and SHA-256 hash, so unchanged files are skipped, changed ones re-read, and the same bytes under a different name are recognised as a duplicate. Every run and every file's outcome is logged and shown live in Admin.
