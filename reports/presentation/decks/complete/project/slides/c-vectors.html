In the same database: pgvector in Postgres, so a search can be narrowed by supplier, type or the documents ticked

Runs locally: the embedding model runs on our own server; no clause text leaves it to be indexed

Indexing is what makes clause questions work. Each clause is turned into a vector, 384 numbers that capture its meaning, using the open BGE-small embedding model, and stored next to the clause in the same Postgres database through pgvector. A question is turned into a vector the same way, and the closest clauses are returned: “what happens if we end this contract early?” finds the liquidated-damages clause with a 74 percent match although it never says “end early”. Because vectors and terms share one database, a search can be narrowed by supplier, document type or the documents a user has ticked. The embedding model runs on our own server, so clause text does not leave it to be indexed; with no model available a simpler word-based fallback keeps the demo working.
